# USPACE — Local-first AI Writing Workspace

مساحة كتابة عربية شخصية تجمع بين **Rich Text** و**Markdown** مع حفظ محلي وذكاء اصطناعي اختياري. يعتمد محرر Rich Text على Tiptap 3 مع امتدادات مجانية مفتوحة المصدر، ولا يحتاج إلى خدمة Tiptap مدفوعة.

## المحرر

- **المحرر المرئي:** عناوين H1–H6 (H1–H3 في الشريط حاليًا)، عريض ومائل وتسطير وشطب وتظليل وروابط وقوائم نقطية ورقمية وقوائم مهام واقتباسات وفواصل وكود.
- **جداول فعلية:** إدراج جدول وتحرير الخلايا مباشرة، إضافة/حذف الصفوف والأعمدة، دمج وتقسيم الخلايا، صف وعمود عناوين، وتعديل عرض الأعمدة بالسحب.
- **تنسيق النص:** تغيير الخط الافتراضي وحجمه على مستوى المستند، تغيير خط التحديد وحجمه ولونه، ومحاذاة الفقرات.
- **الصور:** روابط صور HTTPS مع تغيير الحجم؛ تحميل الصور محليًا إلى خادم غير موجود في هذه النسخة.
- **زر MD:** التبديل إلى مصدر Markdown وتحريره. وضع المعاينة يدعم GitHub Flavored Markdown بواسطة Marked، مع تنظيف HTML باستخدام DOMPurify.
- **التصدير:** ملفات `.md` أو `.html`، وملف JSON احتياطي يحتوي النسخة الكاملة من Rich Text.
- **الاستعادة:** استيراد `.md`، أو استيراد نسخة JSON كمساحات وصفحات جديدة دون حذف الموجود؛ تتم العملية ذريًا عبر IndexedDB.

**قاعدة سلامة البيانات:** يُحفظ `page.richDoc` بصيغة Tiptap JSON لحفظ التنسيقات المرئية الكاملة، و`page.body` بصيغة Markdown للنقل والمشاركة. لا يحتاج أي مستند موجود مسبقًا إلى ترحيل قاعدة البيانات: إذا لم يكن `richDoc` موجودًا يفتح المحرر نص Markdown القديم. تُنشأ نسخ قبل تغيير المحتوى في Rich Text وأيضًا قبل تحرير المصدر عندما توجد تنسيقات مرئية.

**حدود Markdown التقنية:** Markdown لا يستطيع تمثيل لون الخط أو حجم الخط أو دمج الخلايا أو تنسيق الجداول المعقد. لا تتوقع تطابقًا حرفيًا للصيغتين. يعرض التطبيق تحذيرًا عند فتح Markdown لمستند غني، وتبقى بيانات Rich JSON الأصلية محفوظة في سجل النسخ. امتداد Tiptap Markdown لا يزال Beta وقد لا يدعم بعض تراكيب Markdown المخصصة مثل التعليقات والحواشي ومعادلات LaTeX. **لا تدّعِ دعمًا كاملًا لكل امتدادات Markdown دون اختبار إضافي.**

## مفتاح DeepSeek الشخصي

- أدخل مفتاح API بنفسك في لوحة AI؛ يبقى في **ذاكرة الصفحة** افتراضيًا فقط.
- خيار حفظ مشفر محلي باستخدام Web Crypto وAES-GCM وPBKDF2-SHA256 مع عبارة مرور يختارها المستخدم؛ يُحفظ النص المشفر في IndexedDB، وليس المفتاح الصريح.
- عند إرسال طلب AI، يمر المفتاح عبر Cloudflare Pages Function إلى DeepSeek مؤقتًا عبر HTTPS؛ هذا ليس اتصالًا يبقي المفتاح داخل الجهاز طوال الوقت.
- لا تحفظ مفتاح DeepSeek في المستودع، أو كود الموقع، أو GitHub Actions Secrets من أجل ميزة BYOK. أسرار GitHub `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` مخصصة للنشر فقط.
- يدعم وضع الاتصال القديم باستخدام `DEEPSEEK_API_KEY` و`APP_ACCESS_KEY` المحفوظين في Cloudflare Pages Secrets.
- لا يحمي التشفير المحلي من سكربت ضار يعمل ضمن نفس أصل الصفحة وهي مفتوحة؛ تتطلب الحماية إدارة دقيقة للاعتمادات ومراجعة XSS/CSP.

## التشغيل والبناء

يتطلب Node.js 22 أو أحدث.

```bash
cd uspace
npm install
npm test
npm run build
npm run preview
```

خادم المعاينة العادي يعرض الموقع فقط. للوصول إلى `/api/ai` يلزم بيئة Cloudflare Pages Functions أو Worker مع الإعداد الصحيح.

```bash
npm run deploy
```

**لا تدمج الفرع في `main` قبل نجاح اختبارات CI وتجربة متصفح فعلية.** النشر الإنتاجي في المستودع مرتبط بدمج `main`، أما هذا الفرع فهو تجريبي.

## اختبارات أساسية

- `node --test tests/*.test.js`
- `node --check dist/assets/app.js` بعد البناء
- التحقق من إدخال/قفل/تشفير/فتح مفتاح API، وتجربة اتصال DeepSeek باستخدام مفتاح محدود الصلاحيات
- اختبار Markdown/Rich Text بالتناوب، الاستيراد والاستعادة، دمج الخلايا، اتجاه النص RTL/LTR، وتحريك الأعمدة على الجوال والكمبيوتر
- التأكد من أن النص والمعلومات لا تضيع بعد إعادة تحميل الصفحة أو رجوع النسخ

## لم يكتمل بعد

- التدقيق اليدوي الشامل على أجهزة حقيقية، واختبارات تكامل مرور كامل بين Rich Text وMarkdown.
- رفع الصور من الجهاز ومزامنة المستندات بين الأجهزة.
- سجل فروقات نصية تفصيلي قبل اعتماد كل تعديل AI، وتصميم واجهة كامل بمستوى محررات المستندات الناضجة.
- معالجة جميع تراكيب Markdown غير القياسية (الحواشي، المعادلات، الإضافات الخاصة).

هذه حدود فعلية وليست مزايا متاحة حاليًا.
